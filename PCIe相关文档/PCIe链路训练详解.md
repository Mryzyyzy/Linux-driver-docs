## 链路训练概述

### 1. 什么是链路训练？

**链路训练（Link Training）**是PCIe设备在建立通信之前必须完成的一个**自动协商和配置过程**。它确保两个PCIe设备能够：

- 建立物理连接
- 协商链路参数（速度、宽度）
- 同步时钟
- 优化信号完整性
- 建立可靠的数据传输

### 2. 链路训练的基本流程

```
设备上电/复位
    │
    ├─> 检测阶段（Detect）
    │
    ├─> 轮询阶段（Polling）
    │
    ├─> 配置阶段（Configuration）
    │
    └─> L0状态（正常工作）
```

### 3. 链路训练的特点

- **自动执行**：硬件自动完成，无需软件干预
- **双向协商**：两个设备互相协商参数
- **自适应**：根据链路质量调整参数
- **容错性**：支持降级（速度/宽度降级）

## 为什么需要链路训练

### 1. 解决的实际问题

#### A. 时钟同步问题

```
问题：发送端和接收端没有共享时钟
解决：通过训练序列让CDR锁定
```

#### B. 信号完整性问题

```
问题：不同链路长度、PCB走线导致信号质量不同
解决：通过训练找到最优采样点
```

#### C. 链路参数协商

```
问题：设备支持不同的速度和宽度
解决：协商双方都支持的最高参数
```

#### D. 通道对齐

```
问题：多通道（x2, x4, x8, x16）需要对齐
解决：通过训练序列对齐所有通道
```

### 2. 链路训练的目标

1. **建立物理连接**：确认链路存在且可用
2. **频率锁定**：CDR锁定到数据频率
3. **位锁定**：确定数据位的边界
4. **符号锁定**：确定8b/10b符号边界
5. **通道对齐**：多通道时对齐所有通道
6. **参数协商**：协商速度、宽度等参数
7. **进入L0**：准备正常数据传输

## 链路训练状态机

### 1. LTSSM（Link Training and Status State Machine）

PCIe使用**LTSSM**状态机来管理链路训练：

```
┌─────────┐
│ Detect  │ ──> 检测链路是否存在
└────┬────┘
     │
┌────▼────┐
│ Polling │ ──> 发送训练序列，CDR锁定
└────┬────┘
     │
┌────▼──────────┐
│ Configuration │ ──> 协商参数，对齐通道
└────┬──────────┘
     │
┌────▼────┐
│   L0    │ ──> 正常工作状态
└─────────┘
     │
     ├─> [其他状态：L0s, L1, L2, Recovery等]
```

### 2. 主要状态

| 状态 | 说明 | 持续时间 |
|------|------|---------|
| **Detect** | 检测链路是否存在 | ~24ms |
| **Polling** | 发送训练序列，CDR锁定 | ~12ms |
| **Configuration** | 协商参数，对齐通道 | ~16ms |
| **L0** | 正常工作状态 | 持续 |
| **Recovery** | 重新训练（参数改变时） | ~16ms |

## 训练序列（TS1/TS2）

### 1. 什么是训练序列？

**训练序列（Training Sequence）**是特殊的8b/10b编码数据包，用于链路训练：

- **TS1**：第一类训练序列
- **TS2**：第二类训练序列

### 2. TS1/TS2的结构

```
TS1/TS2包结构:
┌─────────────────────────────────────┐
│ COM符号 (K28.5)                    │ 同步字符
├─────────────────────────────────────┤
│ 16个数据符号                        │
│ - Link Number                       │ 链路号
│ - Lane Number                        │ 通道号
│ - N_FTS                              │ Fast Training Sequences数量
│ - Rate ID                            │ 速率标识
│ - Training Control                   │ 训练控制
│ - ...                                │
└─────────────────────────────────────┘
```

### 3. TS1 vs TS2

| 特性 | TS1 | TS2 |
|------|-----|-----|
| **用途** | 初始训练，CDR锁定 | 参数确认，进入配置 |
| **发送时机** | Polling和Configuration阶段 | Configuration阶段 |
| **内容** | 包含链路参数 | 确认参数 |
| **数量** | 更多 | 较少 |

### 4. 训练序列的作用

```
1. 提供足够的跳变 ──> CDR可以锁定频率
2. 包含链路参数 ──> 协商速度和宽度
3. 通道对齐 ──> 多通道时对齐所有通道
4. 符号锁定 ──> 确定8b/10b符号边界
```

## 各个阶段详解

### 1. Detect阶段（检测阶段）

#### 目的
检测链路是否存在，是否有设备连接。

#### 过程

```
┌─────────┐         ┌─────────┐
│ 设备A   │         │ 设备B   │
│         │         │         │
│ 发送    │         │ 发送    │
│ 检测信号│────────>│ 检测信号│
│         │<────────│         │
└─────────┘         └─────────┘
```

**检测方法：**
- 发送**电气空闲（Electrical Idle）**信号
- 检测接收端是否有信号
- 如果检测到信号，进入下一阶段

#### 时间要求
- 最大24ms
- 如果超时，认为链路不存在

### 2. Polling阶段（轮询阶段）

#### 目的
- 发送训练序列（TS1）
- 让CDR锁定频率
- 建立基本的时钟同步

#### 过程

```
设备A: 发送TS1 ──────────────> 设备B
设备A: <────────────── 发送TS1 设备B

重复发送，直到：
1. CDR锁定频率
2. 检测到有效的TS1
3. 收到对端的TS1
```

**关键步骤：**

```
步骤1: 发送TS1
设备A ──[TS1]──> 设备B

步骤2: CDR锁定
设备B的CDR从TS1中恢复时钟频率

步骤3: 检测TS1
设备B检测到有效的TS1序列

步骤4: 响应TS1
设备B ──[TS1]──> 设备A

步骤5: 双方锁定
双方CDR都锁定，准备进入配置阶段
```

#### TS1内容示例

```
TS1包内容:
- Link Number: 0xFF (未配置)
- Lane Number: 通道号 (0, 1, 2, ...)
- Rate ID: 支持的速度 (Gen1, Gen2, Gen3, ...)
- Training Control: 训练控制位
```

#### 时间要求
- 最大12ms
- 如果超时，可能降级或重试

### 3. Configuration阶段（配置阶段）

#### 目的
- 协商链路参数（速度、宽度）
- 对齐所有通道
- 确认配置参数

#### 子阶段

**Configuration.Complete:**
- 发送TS1，包含链路参数
- 协商链路宽度和速度

**Configuration.Idle:**
- 发送TS2，确认参数
- 准备进入L0状态

#### 过程

```
阶段1: Configuration.Complete
设备A ──[TS1 with params]──> 设备B
设备A <──[TS1 with params]── 设备B
        (协商参数)

阶段2: Configuration.Idle
设备A ──[TS2]──> 设备B
设备A <──[TS2]── 设备B
        (确认参数)

阶段3: 进入L0
双方都收到TS2，参数确认完成
进入L0正常工作状态
```

#### 参数协商

**链路宽度协商：**
```
设备A支持: x1, x2, x4, x8, x16
设备B支持: x1, x2, x4

协商结果: x4 (双方都支持的最大宽度)
```

**链路速度协商：**
```
设备A支持: Gen1, Gen2, Gen3, Gen4
设备B支持: Gen1, Gen2, Gen3

协商结果: Gen3 (双方都支持的最高速度)
```

#### 通道对齐（Lane Alignment）

对于多通道链路（x2, x4, x8, x16），需要对齐所有通道：

```
通道0: ──[TS1]──>
通道1: ──[TS1]──>
通道2: ──[TS1]──>
通道3: ──[TS1]──>

对齐过程:
1. 每个通道独立训练
2. 检测所有通道的TS1
3. 对齐所有通道的符号边界
4. 确保所有通道同步
```

#### 时间要求
- 最大16ms
- 如果超时，可能降级参数

### 4. L0状态（正常工作）

#### 目的
链路训练完成，可以正常传输数据。

#### 特点
- 发送正常的数据包（TLP, DLLP）
- CDR持续跟踪相位
- 监控链路状态
- 如果出现问题，进入Recovery状态重新训练

## 链路参数协商

### 1. 链路宽度（Link Width）

#### 支持的宽度
- x1: 1个通道
- x2: 2个通道
- x4: 4个通道
- x8: 8个通道
- x16: 16个通道

#### 协商过程

```
设备A: 支持 x1, x2, x4, x8, x16
设备B: 支持 x1, x2, x4

协商:
1. 设备A在TS1中声明支持: x16, x8, x4, x2, x1
2. 设备B在TS1中声明支持: x4, x2, x1
3. 双方选择共同支持的最大值: x4
4. 配置为x4链路
```

#### 降级情况

如果协商失败，可能降级：
```
尝试: x16 ──> 失败
尝试: x8  ──> 失败
尝试: x4  ──> 成功 ✓
最终: x4链路
```

### 2. 链路速度（Link Speed）

#### 支持的速度

| 代 | 速度 | 说明 |
|---|------|------|
| Gen1 | 2.5 GT/s | PCIe 1.0 |
| Gen2 | 5.0 GT/s | PCIe 2.0 |
| Gen3 | 8.0 GT/s | PCIe 3.0 |
| Gen4 | 16.0 GT/s | PCIe 4.0 |
| Gen5 | 32.0 GT/s | PCIe 5.0 |

#### 协商过程

```
设备A: 支持 Gen1, Gen2, Gen3, Gen4
设备B: 支持 Gen1, Gen2, Gen3

协商:
1. 从最高速度开始尝试: Gen4
2. 设备B不支持Gen4，降级到Gen3
3. 双方都支持Gen3
4. 配置为Gen3链路
```

#### 速率标识（Rate ID）

在TS1/TS2中使用Rate ID字段标识支持的速度：
```
Rate ID = 0x1: Gen1 (2.5 GT/s)
Rate ID = 0x2: Gen2 (5.0 GT/s)
Rate ID = 0x3: Gen3 (8.0 GT/s)
Rate ID = 0x4: Gen4 (16.0 GT/s)
Rate ID = 0x5: Gen5 (32.0 GT/s)
```

### 3. 其他参数

#### N_FTS（Number of Fast Training Sequences）
- 快速训练序列数量
- 用于快速重新同步
- 在TS1/TS2中协商

#### 链路号（Link Number）
- 多端口设备使用
- 区分不同的链路

## 实际示例

### 示例1：简单的x1 Gen3链路训练

```
时间轴:
0ms    12ms   24ms   40ms
│      │      │      │
├──────┼──────┼──────┤
│Detect│Poll  │Config│ L0
└──────┴──────┴──────┘

详细过程:

0-24ms: Detect阶段
- 设备A检测到设备B
- 设备B检测到设备A
- 确认链路存在

24-36ms: Polling阶段
设备A: ──[TS1]──> 设备B
设备B: CDR锁定，检测到TS1
设备B: ──[TS1]──> 设备A
设备A: CDR锁定，检测到TS1
双方CDR都锁定

36-52ms: Configuration阶段
设备A: ──[TS1: x1, Gen3]──> 设备B
设备B: ──[TS1: x1, Gen3]──> 设备A
        (协商参数: x1宽度, Gen3速度)

设备A: ──[TS2]──> 设备B
设备B: ──[TS2]──> 设备A
        (确认参数)

52ms+: L0状态
- 链路训练完成
- 可以正常传输数据
```

### 示例2：x4 Gen3链路训练（带降级）

```
初始尝试: x4 Gen3

Detect阶段: ✓ 成功
Polling阶段: ✓ 成功 (所有4个通道)

Configuration阶段:
通道0: ✓ 成功
通道1: ✓ 成功
通道2: ✗ 失败 (信号质量问题)
通道3: ✓ 成功

结果: 降级到 x2 Gen3
- 只使用通道0和通道1
- 通道2和通道3禁用
- 速度保持Gen3
```

### 示例3：速度降级

```
初始尝试: x4 Gen4

Detect阶段: ✓ 成功
Polling阶段: ✗ 失败 (Gen4信号质量差)

降级到: x4 Gen3

Detect阶段: ✓ 成功
Polling阶段: ✓ 成功
Configuration阶段: ✓ 成功

最终: x4 Gen3链路
```

## 故障排查

### 1. 链路训练失败的原因

#### A. 物理连接问题
```
症状: 停留在Detect阶段
原因: 
- 设备未连接
- 连接器问题
- 电缆问题
解决: 检查物理连接
```

#### B. 信号完整性问题
```
症状: Polling阶段失败
原因:
- PCB走线太长
- 信号衰减
- 串扰
解决: 检查信号完整性，可能需要降级速度
```

#### C. 参数不兼容
```
症状: Configuration阶段失败
原因:
- 速度不兼容
- 宽度不兼容
解决: 检查设备支持的能力
```

#### D. 电源问题
```
症状: 训练不稳定
原因:
- 电源不稳定
- 电源噪声
解决: 检查电源质量
```

### 2. 调试方法

#### A. 查看链路状态

```bash
# 查看链路宽度和速度
lspci -vvv | grep -A 5 "LnkSta"

# 输出示例:
LnkSta: Speed 8GT/s, Width x4
```

#### B. 查看训练日志

```bash
# 查看内核日志
dmesg | grep -i pcie

# 可能看到:
[   1.234] pcieport 0000:00:01.0: Link Training...
[   1.250] pcieport 0000:00:01.0: Link up at 8GT/s x4
```

#### C. 使用PCIe调试工具

```bash
# 查看配置空间
setpci -s 00:01.0 CAP_EXP+0x10.l

# 查看链路状态
setpci -s 00:01.0 CAP_EXP+0x12.w
```

### 3. 常见问题

#### Q: 链路训练需要多长时间？
A: 正常情况下：
- Detect: ~24ms
- Polling: ~12ms
- Configuration: ~16ms
- 总计: ~52ms

#### Q: 可以手动控制链路训练吗？
A: 通常不可以，链路训练是硬件自动完成的。但可以通过配置寄存器影响某些参数。

#### Q: 训练失败会怎样？
A: 设备会尝试降级（降低速度或宽度），如果完全失败，链路不会建立。

#### Q: 如何强制重新训练？
A: 可以通过软件触发链路重新训练：
```c
// 在驱动中
pcie_capability_set_word(pdev, PCI_EXP_LNKCTL, 
                         PCI_EXP_LNKCTL_RL);
```

## 链路训练与CDR的关系

### 1. CDR在链路训练中的作用

```
Polling阶段:
1. 发送TS1训练序列
2. TS1提供足够的跳变
3. CDR从TS1中锁定频率
4. CDR相位对齐

Configuration阶段:
1. 继续发送TS1/TS2
2. CDR持续跟踪相位
3. 优化采样点
4. 确保所有通道同步
```

### 2. 训练序列对CDR的重要性

```
TS1/TS2特点:
- 8b/10b编码，保证跳变
- 每5个位至少有1个跳变
- 提供足够的边沿用于CDR锁定
- 包含同步字符（K28.5）
```

### 3. 多通道CDR同步

```
x4链路示例:
通道0: CDR锁定 ──> 时钟0
通道1: CDR锁定 ──> 时钟1
通道2: CDR锁定 ──> 时钟2
通道3: CDR锁定 ──> 时钟3

对齐过程:
1. 每个通道独立CDR锁定
2. 检测所有通道的TS1
3. 对齐所有通道的符号边界
4. 确保时钟同步
```

## 高级主题

### 1. 链路重新训练（Recovery）

当链路参数需要改变时，会进入Recovery状态重新训练：

```
触发条件:
- 速度改变
- 宽度改变
- 链路错误
- 软件请求

过程:
L0 ──> Recovery ──> Polling ──> Configuration ──> L0
```

### 2. 链路状态（L0s, L1, L2）

除了L0，PCIe还支持低功耗状态：

```
L0:  正常工作
L0s: 快速休眠（保持时钟）
L1:  深度休眠（关闭部分电路）
L2:  完全休眠（关闭大部分电路）

从低功耗状态恢复时，可能需要重新训练
```

### 3. 链路训练优化

现代PCIe实现使用各种优化：

```
- 快速训练: 减少训练时间
- 自适应均衡: 根据链路质量调整
- 预加重/去加重: 改善信号质量
- 接收均衡: 补偿信号衰减
```

## 总结

### 链路训练的关键点

1. **自动过程**：硬件自动完成，无需软件干预
2. **双向协商**：两个设备互相协商参数
3. **多阶段**：Detect → Polling → Configuration → L0
4. **容错性**：支持降级以建立链路
5. **与CDR配合**：训练序列帮助CDR锁定

### 训练序列的作用

1. **提供跳变**：让CDR可以锁定频率
2. **参数协商**：协商速度和宽度
3. **通道对齐**：多通道时对齐所有通道
4. **符号锁定**：确定8b/10b符号边界

### 实际应用

- 设备上电时自动执行
- 参数改变时重新训练
- 故障恢复时重新训练
- 通常需要50-100ms完成

链路训练是PCIe能够可靠工作的基础，它确保了即使在不同的硬件配置和信号条件下，PCIe设备也能建立稳定的通信链路。
