# PCIe ranges 属性格式详解

## 一、ranges 属性的作用

`ranges` 属性用于定义**子地址空间（PCIe 地址）到父地址空间（系统地址）的映射关系**。

对于 PCIe host bridge：
- **子地址空间**：PCIe 设备看到的地址（PCIe 地址空间）
- **父地址空间**：系统物理地址空间
- **ranges**：定义两者之间的映射关系

## 二、ranges 格式的组成

### 2.1 基本格式

```
ranges = <子地址空间 父地址空间 大小>;
```

每个映射条目的格式取决于：
- **子节点的 `#address-cells`**：子地址空间用几个 cell
- **父节点的 `#address-cells`**：父地址空间用几个 cell
- **子节点的 `#size-cells`**：大小用几个 cell

### 2.2 PCIe host bridge 的配置

```dts
pcie: pcie@ff000000 {
    #address-cells = <3>;  // PCIe 地址用 3 个 cell
    #size-cells = <2>;     // 大小用 2 个 cell
    // ...
    ranges = <...>;
};
```

**关键点：**
- `#address-cells = <3>`：PCIe 地址空间用 3 个 cell
- `#size-cells = <2>`：大小用 2 个 cell
- 父节点（通常是根节点）的 `#address-cells = <2>`（ARM64 系统，64位地址）

## 三、为什么是 7 个元素？

### 3.1 元素分解

以这个例子为例：
```dts
ranges = <0x81000000 0x0 0x00000000 0x0 0x80000000 0x0 0x00010000>;
```

**7 个元素的组成：**

```
┌─────────────────────────────────────────────────────────┐
│ 元素 1-3：子地址空间（PCIe 地址）- 3 个 cell            │
├─────────────────────────────────────────────────────────┤
│ 0x81000000  │ 第一个 cell：地址空间类型标志              │
│             │ Bit 31: 非重定位标志                      │
│             │ Bit 30: 预取标志（Prefetch）                │
│             │ Bit 25-24: 地址空间类型                    │
│             │   00 = 配置空间                            │
│             │   01 = I/O 空间 (0x81000000)              │
│             │   10 = Memory 32位 (0x82000000)            │
│             │   11 = Memory 64位 (0x83000000)            │
│             │ Bit 23-16: Bus 号（ranges 中通常为 0）      │
│             │ Bit 15-11: Device 号（ranges 中通常为 0）   │
│             │ Bit 10-8: Function 号（ranges 中通常为 0） │
│             │ Bit 7-0: 寄存器号（ranges 中通常为 0）      │
│             │                                             │
│             │ 对于 ranges，这个 cell 主要表示地址空间类型 │
│             │ 0x81000000 = I/O 空间                      │
│             │ 0x82000000 = Memory 空间                  │
│             │ 0x83000000 = Prefetchable Memory 空间      │
├─────────────────────────────────────────────────────────┤
│ 0x0         │ 第二个 cell：PCIe 地址高 32 位             │
│             │ 对于 32 位地址空间，通常为 0                │
├─────────────────────────────────────────────────────────┤
│ 0x00000000  │ 第三个 cell：PCIe 地址低 32 位             │
│             │ PCIe 地址空间的起始地址                    │
│             │ 对于 I/O：从 0x00000000 开始              │
├─────────────────────────────────────────────────────────┤
│ 元素 4-5：父地址空间（系统地址）- 2 个 cell              │
├─────────────────────────────────────────────────────────┤
│ 0x0         │ 系统物理地址高 32 位                      │
├─────────────────────────────────────────────────────────┤
│ 0x80000000  │ 系统物理地址低 32 位                      │
│             │ 系统物理地址 = 0x80000000                 │
├─────────────────────────────────────────────────────────┤
│ 元素 6-7：大小 - 2 个 cell                              │
├─────────────────────────────────────────────────────────┤
│ 0x0         │ 大小高 32 位（通常为 0）                  │
├─────────────────────────────────────────────────────────┤
│ 0x00010000  │ 大小低 32 位                              │
│             │ 大小 = 64KB (0x10000)                     │
└─────────────────────────────────────────────────────────┘
```

**关键理解：**
- `#address-cells = <3>` 表示**地址用 3 个 cell**，**全部都是地址的一部分**
- **第一个 cell (0x81000000)**：地址空间类型标志 + Bus/Dev/Func/Reg 信息
  - 这是地址的**第一部分**，不是独立的标志
  - 在 ranges 中，Bus/Dev/Func/Reg 通常为 0，主要表示地址空间类型
- **第二、三个 cell (0x0 0x00000000)**：实际的 PCIe 地址值（64位地址）
  - 这是地址的**第二、三部分**
- 所以**总共是 3 个 cell 表示 PCIe 地址**，符合 `#address-cells = <3>`

**重要说明：**
- 第一个 cell **也是地址的一部分**，不是独立的标志
- 3 个 cell 共同组成完整的 PCIe 地址
- 在 ranges 中，第一个 cell 主要用来区分地址空间类型（I/O/Memory）

### 3.2 计算公式

```
ranges 元素总数 = 子地址cells + 父地址cells + 大小cells
                = 3 + 2 + 2
                = 7
```

**其中：**
- **子地址 cells = 3**：由 `#address-cells = <3>` 决定
- **父地址 cells = 2**：由父节点的 `#address-cells = <2>` 决定（ARM64 系统）
- **大小 cells = 2**：由 `#size-cells = <2>` 决定

## 四、详细示例解析

### 4.1 I/O 空间映射

```dts
ranges = <0x81000000 0x0 0x00000000 0x0 0x80000000 0x0 0x00010000>;
```

**含义：**
- **PCIe I/O 地址** `[0x00000000, 0x00010000)` 
- **映射到系统物理地址** `[0x80000000, 0x80010000)`
- **大小**：64KB (0x10000)

**映射关系：**
```
PCIe 设备访问 I/O 地址 0x0000
    ↓
映射到系统物理地址 0x80000000
    ↓
CPU/系统访问 0x80000000
```

### 4.2 Memory 空间映射

```dts
ranges = <0x82000000 0x0 0x40000000 0x0 0x40000000 0x0 0x40000000>;
```

**含义：**
- **PCIe Memory 地址** `[0x40000000, 0x80000000)`
- **映射到系统物理地址** `[0x40000000, 0x80000000)`
- **大小**：1GB (0x40000000)

**元素分解：**
```
0x82000000  │ Memory 空间类型
0x0         │ PCIe 地址高 32 位
0x40000000  │ PCIe 地址低 32 位（起始地址）
0x0         │ 系统地址高 32 位
0x40000000  │ 系统地址低 32 位（映射地址）
0x0         │ 大小高 32 位
0x40000000  │ 大小低 32 位（1GB）
```

### 4.3 完整的 ranges 示例

```dts
pcie: pcie@ff000000 {
    compatible = "snps,dw-pcie";
    #address-cells = <3>;
    #size-cells = <2>;
    device_type = "pci";
    
    ranges = <0x81000000 0x0 0x00000000 0x0 0x80000000 0x0 0x00010000   /* I/O */
              0x82000000 0x0 0x40000000 0x0 0x40000000 0x0 0x40000000>; /* MEM */
};
```

**两个映射条目：**

1. **I/O 映射：**
   - PCIe I/O `[0x0, 0x10000)` → 系统地址 `[0x80000000, 0x80010000)`
   - 大小：64KB

2. **Memory 映射：**
   - PCIe Memory `[0x40000000, 0x80000000)` → 系统地址 `[0x40000000, 0x80000000)`
   - 大小：1GB

## 五、地址空间类型标志

### 5.1 标志位定义

```
0x81000000 = I/O 空间
0x82000000 = Memory 空间（非预取）
0x83000000 = Prefetchable Memory 空间
```

**标志位格式：**
```
Bit 31-24: 地址空间类型
  - 0x81 = I/O
  - 0x82 = Memory (non-prefetchable)
  - 0x83 = Memory (prefetchable)

Bit 23-16: 保留

Bit 15-0: 其他标志位
```

### 5.2 实际使用

```dts
// I/O 空间映射
ranges = <0x81000000 ...>;  // I/O 空间

// Memory 空间映射（非预取）
ranges = <0x82000000 ...>;  // Memory 空间

// Memory 空间映射（可预取）
ranges = <0x83000000 ...>;  // Prefetchable Memory
```

## 六、不同架构的差异

### 6.1 ARM64 系统（64位地址）

```dts
/ {
    #address-cells = <2>;  // 64位地址用 2 个 cell
    #size-cells = <2>;     // 64位大小用 2 个 cell
    
    pcie {
        #address-cells = <3>;  // PCIe 地址用 3 个 cell
        #size-cells = <2>;     // 大小用 2 个 cell
        
        // ranges = <子地址(3) 父地址(2) 大小(2)> = 7 个 cell
        ranges = <0x81000000 0x0 0x00000000 0x0 0x80000000 0x0 0x00010000>;
    };
};
```

### 6.2 ARM32 系统（32位地址）

```dts
/ {
    #address-cells = <1>;  // 32位地址用 1 个 cell
    #size-cells = <1>;     // 32位大小用 1 个 cell
    
    pcie {
        #address-cells = <3>;  // PCIe 地址用 3 个 cell
        #size-cells = <1>;     // 大小用 1 个 cell
        
        // ranges = <子地址(3) 父地址(1) 大小(1)> = 5 个 cell
        ranges = <0x81000000 0x0 0x00000000 0x80000000 0x00010000>;
    };
};
```

**注意：** 在 ARM32 系统中，ranges 只有 **5 个元素**（3 + 1 + 1 = 5）

## 七、ranges 的作用机制

### 7.1 地址转换流程

```
PCIe 设备发起访问
    ├─ 地址：PCIe 地址空间（例如 0x40000000）
    ↓
PCIe host bridge 查找 ranges
    ├─ 找到匹配的映射条目
    ├─ 提取父地址（系统地址）
    └─ 计算偏移量
    ↓
转换为系统物理地址
    ├─ 系统地址 = 父地址 + (PCIe地址 - 子地址起始)
    └─ 例如：0x40000000 + (0x40000000 - 0x40000000) = 0x40000000
    ↓
系统访问物理地址
```

### 7.2 实际示例

```dts
ranges = <0x82000000 0x0 0x40000000 0x0 0x40000000 0x0 0x40000000>;
```

**当 PCIe 设备访问地址 0x40001000 时：**

1. PCIe 地址：`0x40001000`
2. 查找 ranges：找到 Memory 映射条目
3. 子地址起始：`0x40000000`
4. 父地址起始：`0x40000000`
5. 偏移量：`0x40001000 - 0x40000000 = 0x1000`
6. 系统地址：`0x40000000 + 0x1000 = 0x40001000`

## 八、总结

### 8.1 为什么是 7 个元素？

**答案：**
```
ranges 元素数 = 子地址cells + 父地址cells + 大小cells
              = 3 + 2 + 2
              = 7
```

**其中：**
- **3 个 cell**：PCIe 地址空间（类型标志 + 64位地址）
- **2 个 cell**：系统物理地址（64位，ARM64）
- **2 个 cell**：大小（64位）

### 8.2 元素含义

| 位置 | 值 | 含义 | 说明 |
|------|-----|------|------|
| 1 | `0x81000000` | PCIe 地址第 1 个 cell | 地址空间类型标志 + Bus/Dev/Func/Reg（ranges 中通常为 0） |
| 2 | `0x0` | PCIe 地址第 2 个 cell | PCIe 地址高 32 位（64位地址的上半部分） |
| 3 | `0x00000000` | PCIe 地址第 3 个 cell | PCIe 地址低 32 位（64位地址的下半部分，起始地址） |
| 4 | `0x0` | 系统地址第 1 个 cell | 系统物理地址高 32 位（64位地址的上半部分） |
| 5 | `0x80000000` | 系统地址第 2 个 cell | 系统物理地址低 32 位（64位地址的下半部分，映射地址） |
| 6 | `0x0` | 大小第 1 个 cell | 大小高 32 位（64位大小的上半部分） |
| 7 | `0x00010000` | 大小第 2 个 cell | 大小低 32 位（64位大小的下半部分，64KB） |

**关键点：**
- **元素 1-3**：PCIe 地址的 3 个 cell（符合 `#address-cells = <3>`）
- **元素 4-5**：系统地址的 2 个 cell（符合父节点的 `#address-cells = <2>`）
- **元素 6-7**：大小的 2 个 cell（符合 `#size-cells = <2>`）
- **第一个 cell 也是地址的一部分**，不是独立的标志，它包含地址空间类型信息

### 8.3 关键点

1. **元素数量取决于 `#address-cells` 和 `#size-cells`**
2. **ARM64 系统**：父地址用 2 个 cell（64位），所以是 7 个元素
3. **ARM32 系统**：父地址用 1 个 cell（32位），所以是 5 个元素
4. **第一个元素**：地址空间类型标志，不是地址的一部分
