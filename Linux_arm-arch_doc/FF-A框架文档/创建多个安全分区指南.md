# 如何创建多个安全分区（Secure Partition）

## 概述

在 ATF 的 FF-A 框架中，可以创建和管理多个独立的安全分区（Secure Partition，SP）。每个安全分区运行在隔离的环境中，提供独立的安全服务。

**注意**：
- **SPMD（Secure Partition Manager Dispatcher）**：通常只有一个，位于 EL3，负责路由 FF-A 调用
- **安全分区（SP）**：可以有多个，每个提供不同的安全服务

本文档说明如何创建和管理多个安全分区。

---

## 1. 前提条件

### 1.1 硬件要求

要支持多个安全分区，通常需要：

- **S-EL2 SPMC 模式**（推荐）：
  - 需要 **FEAT_SEL2** 架构扩展支持
  - SPMC 运行在 S-EL2
  - 支持多个 S-EL1 或 S-EL0 分区

- **EL3 SPMC 模式**（受限）：
  - EL3 SPMC 通常只支持单个 S-EL1 分区
  - 可以通过 `SPMC_AT_EL3_SEL0_SP=1` 支持 S-EL0 分区

### 1.2 构建选项

```bash
# S-EL2 SPMC 模式（支持多个分区）
SPD=spmd
SPMD_SPM_AT_SEL2=1        # SPMC 运行在 S-EL2
SP_LAYOUT_FILE=<path>     # 必需：安全分区布局文件

# EL3 SPMC 模式（通常只支持单个分区）
SPD=spmd
SPMC_AT_EL3=1             # SPMC 运行在 EL3
SPMC_AT_EL3_SEL0_SP=1     # 可选：支持 S-EL0 分区
```

## 2. 创建安全分区的步骤

### 2.1 步骤概览

创建多个安全分区需要以下步骤：

1. **准备安全分区二进制镜像**
2. **创建分区清单文件（Manifest）**
3. **创建分区布局文件（SP_LAYOUT_FILE）**
4. **编译和构建**
5. **验证分区加载**

### 2.2 步骤 1：准备安全分区二进制镜像

每个安全分区需要一个可执行二进制镜像文件（`.bin`）。

**安全分区镜像要求**：
- 必须实现 FF-A 接口
- 必须符合 FF-A 规范
- 可以是：
  - 自定义的安全服务
  - 基于现有框架（如 OP-TEE、Hafnium SP 等）
  - 重新利用的代码（如 EDK2 MM）

**示例**：
```bash
# 假设你已经编译好了安全分区镜像
sp1.bin    # 安全分区 1 的二进制镜像
sp2.bin    # 安全分区 2 的二进制镜像
sp3.bin    # 安全分区 3 的二进制镜像
```

### 2.3 步骤 2：创建分区清单文件（Manifest）

每个安全分区需要一个清单文件（Manifest），使用设备树（Device Tree）格式（`.dts`）。

清单文件定义了分区的属性，包括：

```dts
/dts-v1/;

/ {
    compatible = "arm,ffa-manifest-1.0";
    
    description = "Secure Partition 1 - Encryption Service";
    
    ffa-version = <0x00010002>;  // FF-A v1.2
    
    uuid = <0x12345678 0x1234 0x1234 0x1234 0x123456789abc>;
    
    id = <0x8001>;  // 分区 ID（0x8001 - 0xFFFE）
    
    execution-ctx-count = <1>;     // 执行上下文数量
    exception-level = <0x2>;       // S-EL1 (0x2)
    execution-state = <0>;         // AArch64 (0)
    
    xlat-granule = <0>;            // 4KB (0)
    
    // 内存区域定义
    memory-regions {
        // 代码和数据区域
        sp1_region {
            base-address = <0x80000000>;
            pages-count = <0x100>;  // 1MB
        };
        
        // 堆区域
        heap {
            base-address = <0x80100000>;
            pages-count = <0x100>;  // 1MB
        };
        
        // 栈区域
        stack {
            base-address = <0x80200000>;
            pages-count = <0x10>;   // 64KB
        };
    };
    
    // 消息传递能力
    rx-tx-buffer {
        compatible = "arm,ffa-manifest-rx_tx-buffer";
        rx-buffer-size = <0x1000>;   // 4KB
        tx-buffer-size = <0x1000>;   // 4KB
    };
    
    // 分区属性
    messaging-method = <0x3>;  // 支持直接消息和间接消息
};
```

**清单文件关键字段说明**：

| 字段 | 说明 | 必需 |
|------|------|------|
| `compatible` | 清单版本，如 "arm,ffa-manifest-1.0" | ✅ |
| `uuid` | 分区的全局唯一标识符 | ✅ |
| `id` | 分区 ID（0x8001-0xFFFE），可选（可由 SPMC 分配） | ❌ |
| `execution-ctx-count` | 执行上下文数量（vCPU 数量） | ✅ |
| `exception-level` | 异常级别：0x0(EL1), 0x1(S-EL0), 0x2(S-EL1) | ✅ |
| `execution-state` | 执行状态：0(AArch64), 1(AArch32) | ✅ |
| `memory-regions` | 内存区域定义 | ✅ |
| `rx-tx-buffer` | RX/TX 缓冲区配置 | ❌ |
| `messaging-method` | 消息传递方法支持 | ❌ |

**多个分区的清单文件示例**：

```
manifests/
├── sp1.dts    # 安全分区 1 清单
├── sp2.dts    # 安全分区 2 清单
└── sp3.dts    # 安全分区 3 清单
```

### 2.4 步骤 3：创建分区布局文件（SP_LAYOUT_FILE）

分区布局文件是一个 JSON 格式文件，定义了所有安全分区及其镜像和清单文件的路径。

**布局文件格式**：

```json
{
    "SP1": {
        "image": "sp1.bin",
        "pm": "manifests/sp1.dts"
    },
    
    "SP2": {
        "image": "sp2.bin",
        "pm": "manifests/sp2.dts",
        "uuid": "1b1820fe-48f7-4175-8999-d51da00b7c9f"
    },
    
    "SP3": {
        "image": "sp3.bin",
        "pm": "manifests/sp3.dts"
    }
}
```

**布局文件字段说明**：

| 字段 | 说明 | 必需 |
|------|------|------|
| `"SP1"`, `"SP2"`, etc. | 分区名称（任意字符串） | ✅ |
| `image` | 二进制镜像文件路径（相对于布局文件） | ✅ |
| `pm` | 分区清单文件路径（相对于布局文件） | ✅ |
| `uuid` | UUID（可选，如果不提供则从清单文件中提取） | ❌ |
| `size` | 镜像大小（可选，默认 0x100000） | ❌ |

**文件路径**：
- 所有路径都是**相对于布局文件所在目录**
- 布局文件可以放在 ATF 源码树外
- 镜像和清单文件的路径必须正确

**示例目录结构**：

```
/home/user/my_sp_project/
├── sp_layout.json          # 分区布局文件
├── images/
│   ├── sp1.bin
│   ├── sp2.bin
│   └── sp3.bin
└── manifests/
    ├── sp1.dts
    ├── sp2.dts
    └── sp3.dts
```

对应的 `sp_layout.json`：

```json
{
    "SP1": {
        "image": "images/sp1.bin",
        "pm": "manifests/sp1.dts"
    },
    "SP2": {
        "image": "images/sp2.bin",
        "pm": "manifests/sp2.dts"
    },
    "SP3": {
        "image": "images/sp3.bin",
        "pm": "manifests/sp3.dts"
    }
}
```

### 2.5 步骤 4：编译和构建

使用构建系统编译 ATF 并包含安全分区：

```bash
# S-EL2 SPMC 模式（支持多个分区）
make \
    CROSS_COMPILE=aarch64-none-elf- \
    PLAT=fvp \
    SPD=spmd \
    ARM_ARCH_MINOR=5 \
    BRANCH_PROTECTION=1 \
    CTX_INCLUDE_PAUTH_REGS=1 \
    ENABLE_FEAT_MTE2=1 \
    BL32=<path-to-hafnium-binary> \
    BL33=<path-to-bl33-binary> \
    SP_LAYOUT_FILE=/home/user/my_sp_project/sp_layout.json \
    all fip
```

**构建过程**：

1. **解析布局文件**：`sp_mk_generator.py` 解析 `SP_LAYOUT_FILE`
2. **生成构建文件**：生成 `sp_gen.mk` 包含分区信息
3. **处理清单文件**：将 `.dts` 清单文件编译为 `.dtb`
4. **打包分区**：使用 `sptool` 将镜像和清单打包为 `.pkg` 文件
5. **添加到 FIP**：将分区包添加到 Firmware Image Package (FIP)

**构建输出**：

```
build/fvp/release/
├── sp_gen.mk              # 生成的分区构建文件
├── sp_list_fragment.dts   # 生成的分区列表片段
├── sp1.pkg                # 安全分区 1 包
├── sp2.pkg                # 安全分区 2 包
├── sp3.pkg                # 安全分区 3 包
└── fip.bin                # 包含所有分区的 FIP 镜像
```

### 2.6 步骤 5：验证分区加载

启动系统后，可以通过以下方式验证分区是否加载：

1. **检查启动日志**：
   ```
   INFO: Loading Secure Partition 1...
   INFO: Loading Secure Partition 2...
   INFO: Loading Secure Partition 3...
   ```

2. **使用 FF-A 接口查询分区**：
   - 调用 `FFA_PARTITION_INFO_GET` 获取所有分区信息
   - 检查返回的分区列表

3. **测试分区服务**：
   - 通过 `FFA_MSG_SEND_DIRECT_REQ` 发送消息到分区
   - 验证分区响应

## 3. 分区配置示例

### 3.1 示例 1：三个独立的安全服务分区

**场景**：创建三个安全分区，分别提供加密、认证和密钥管理服务。

**sp_layout.json**：

```json
{
    "EncryptionSP": {
        "image": "images/encryption_sp.bin",
        "pm": "manifests/encryption_sp.dts"
    },
    
    "AuthenticationSP": {
        "image": "images/auth_sp.bin",
        "pm": "manifests/auth_sp.dts"
    },
    
    "KeyManagerSP": {
        "image": "images/keymgr_sp.bin",
        "pm": "manifests/keymgr_sp.dts"
    }
}
```

**manifests/encryption_sp.dts**：

```dts
/dts-v1/;

/ {
    compatible = "arm,ffa-manifest-1.0";
    description = "Encryption Service Partition";
    ffa-version = <0x00010002>;
    uuid = <0x12345678 0x1234 0x5678 0x9abc 0xdef012345678>;
    id = <0x8001>;
    execution-ctx-count = <1>;
    exception-level = <0x2>;  // S-EL1
    execution-state = <0>;    // AArch64
    xlat-granule = <0>;       // 4KB
    
    memory-regions {
        sp_code {
            base-address = <0x80000000>;
            pages-count = <0x100>;
        };
        sp_heap {
            base-address = <0x80100000>;
            pages-count = <0x100>;
        };
    };
};
```

### 3.2 示例 2：不同异常级别的分区

**场景**：创建一个 S-EL1 分区和一个 S-EL0 分区。

```json
{
    "SEL1_SP": {
        "image": "images/sel1_sp.bin",
        "pm": "manifests/sel1_sp.dts"
    },
    
    "SEL0_SP": {
        "image": "images/sel0_sp.bin",
        "pm": "manifests/sel0_sp.dts"
    }
}
```

**注意**：S-EL0 分区需要 SPMC 在 S-EL2 运行。

## 4. 分区 ID 分配

### 4.1 ID 范围

| ID 范围 | 用途 | 说明 |
|---------|------|------|
| 0x0000 - 0x7FFF | Normal World | 正常世界端点（Hypervisor/OS） |
| 0x8000 | SPMC ID | 安全分区管理器核心 |
| 0x8001 - 0xFFFE | Secure Partitions | 安全分区 ID |
| 0xFFFF | SPMD 端点 | SPMD 直接消息端点 |

### 4.2 ID 分配方式

1. **显式分配**：在清单文件的 `id` 字段中指定
2. **自动分配**：如果不指定，SPMC 会自动分配

**建议**：
- 为每个分区显式分配 ID，便于管理和调试
- 使用有意义的 ID 范围（如 0x8001-0x8100 用于服务分区）

## 5. 常见问题

### 5.1 最多可以创建多少个分区？

- **理论上**：ID 范围允许最多约 32766 个分区（0x8001-0xFFFE）
- **实际上**：受内存、性能和管理复杂度限制
- **建议**：根据实际需求创建，通常几个到几十个分区

### 5.2 分区之间如何通信？

分区之间通过 FF-A 接口通信：

- **直接消息**：`FFA_MSG_SEND_DIRECT_REQ`（小数据，64 字节）
- **间接消息**：`FFA_MSG_SEND2`（大数据，通过 RX/TX 缓冲区）
- **内存共享**：`FFA_MEM_SHARE`（共享内存区域）

### 5.3 如何更新分区？

1. 重新编译分区镜像
2. 更新布局文件（如需要）
3. 重新构建 ATF 和 FIP
4. 更新固件

### 5.4 EL3 SPMC 模式支持多个分区吗？

**EL3 SPMC 模式通常只支持单个 S-EL1 分区**。如果需要多个分区，建议使用 **S-EL2 SPMC 模式**。

---

## 6. 最佳实践

1. **明确的职责分离**：每个分区提供特定的安全服务
2. **合理的资源分配**：为每个分区分配适当的内存
3. **唯一的 UUID**：确保每个分区有唯一的 UUID
4. **清晰的命名**：使用有意义的名称和 ID
5. **充分的测试**：在集成前充分测试每个分区
6. **文档化**：记录每个分区的功能和接口
