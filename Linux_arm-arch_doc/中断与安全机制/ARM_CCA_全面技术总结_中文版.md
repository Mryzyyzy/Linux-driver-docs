# ARM 机密计算架构（CCA）- 全面技术总结

## 概述

ARM 机密计算架构（CCA）代表了硬件安全的根本性演进，通过**领域管理扩展（RME）**将传统的 TrustZone 双世界模型扩展为四世界架构。该架构为机密计算工作负载提供硬件强制的隔离，特别针对云、边缘和多方计算场景。

## 1. 四世界安全模型

### 架构层次结构

CCA 引入了四个不同的硬件隔离安全世界，创建了层次化信任模型：

```
最高特权级别
        │
        ▼
┌───── Root 世界 (EL3) ──────┐  管理与安全策略
│   • 固件 (TF-A Monitor)      │
│   • 世界生命周期管理        │
│   • GPT/GPC 配置           │
└─────────────┬─────────────┘
              │
    ┌─────────┼─────────┐
    ▼         ▼         ▼
┌─────┐   ┌─────┐   ┌─────┐
│Secure│   │Realm│   │Non- │
│世界  │   │世界 │   │secure│
│(EL1) │   │(EL1)│   │世界  │
└──────┘   └──────┘   └──────┘
```

### 世界描述

| 世界 | 执行级别 | 主要角色 | 信任要求 |
|-------|----------------|--------------|-------------------|
| **Root 世界** | EL3 | 系统管理、GPT/GPC 配置、世界生命周期 | 可信计算基 |
| **Secure 世界** | EL1/EL0 | 传统 TrustZone：TEE、安全服务 | 向后兼容 |
| **Realm 世界** | EL1/EL0 | 机密计算工作负载 | 仅信任硬件 + Root 固件 |
| **Non-secure 世界** | EL1/EL0 | 通用 OS、应用程序、虚拟机监控器 | 标准软件栈 |

### 关键架构创新

1. **硬件强制层次结构**：Root 世界（EL3）对所有其他世界具有监督控制权
2. **并行世界**：Secure、Realm 和 Non-secure 在相同特权级别（EL1/EL0）运行，但具有不同的安全属性
3. **减少信任基**：Realm 工作负载仅需信任硬件和 Root 固件
4. **向后兼容性**：现有 TrustZone 应用程序继续正常工作

## 2. 颗粒保护检查（GPC）- 核心隔离机制

### GPC 架构

GPC 在**4KB 物理内存颗粒**粒度上提供硬件强制的内存访问控制：

```
内存访问流程：
世界 VA → 世界特定转换 → 物理地址 (PA) → GPC 检查 → 内存
                                                            │
                                                            ▼
                                                     ┌─────────────┐
                                                     │ GPT 查找    │
                                                     │ • 获取 GPI  │
                                                     │ • 权限检查  │
                                                     └─────────────┘
```

### 组件

#### GPT（颗粒保护表）
- **结构**：每个 4KB 物理内存颗粒对应一个条目
- **大小**：约占物理内存的 ~0.024%（每 16KB 4 字节）
- **位置**：由 Root 世界通过 GPTBR_EL3 配置
- **管理**：仅由 Root 世界（EL3）控制

#### GPI（颗粒保护索引）
- **格式**：4 位字段编码访问权限
- **位映射**：
  - **位 3**：Root 世界访问（1=允许，0=拒绝）
  - **位 2**：Secure 世界访问
  - **位 1**：Realm 世界访问
  - **位 0**：Non-secure 世界访问

### 常见 GPI 模式

| GPI (二进制) | 十六进制 | 访问权限 | 典型用途 |
|--------------|-----|-------------------|-------------|
| `0b0010` | 0x2 | 仅 Realm | Realm 私有内存 |
| `0b0100` | 0x4 | 仅 Secure | TrustZone 安全内存 |
| `0b1000` | 0x8 | 仅 Root | 固件、GPT 本身 |
| `0b1111` | 0xF | 所有世界 | 共享内存区域 |
| `0b0011` | 0x3 | Realm + Non-secure | 共享缓冲区 |
| `0b0110` | 0x6 | Secure + Realm | 服务调用 |

### GPC 检查流程

1. **内存访问发起**：CPU 使用当前安全状态发出加载/存储指令
2. **地址转换**：标准 MMU 转换（Stage 1 ± Stage 2）
3. **GPT 查找**：硬件使用 PA 索引 GPT：`granule_index = PA >> 12`
4. **权限检查**：将当前世界与 GPI 位比较
5. **访问裁决**：
   - **允许**：内存访问继续
   - **拒绝**：产生**颗粒保护检查故障**（EC=0x25）

### 安全属性

- **硬件强制**：无法被软件绕过
- **物理地址级别**：保护独立于虚拟映射
- **DMA 保护**：外设 DMA 访问也经过 GPC
- **动态重新分配**：通过更新 GPT 可以在世界间移动内存

## 3. 地址转换架构

### 传统与 CCA 转换对比

**传统 TrustZone**：
```
Guest VA → [Stage 1: EL1 表] → IPA → [Stage 2: EL2 表] → PA
                   │                              │
              (Secure/Non-secure)           (虚拟化)
```

**CCA RME**：
```
每个世界：VA → [Stage 1] → IPA → [可选 Stage 2] → PA → [GPC 检查] → 内存
```

### Realm 特定转换机制

来自 ARM DDI 0487 L.a（第 6436-6438 页）：

1. **Realm EL1&0 转换机制**：Realm 用户和内核空间
2. **Realm EL2&0 转换机制**：Realm 虚拟化支持
3. **Realm EL2 转换机制**：Realm 虚拟机监控器上下文

### 转换独立性

- 每个世界维护独立的转换表
- GPC 提供最终访问控制，无论转换路径如何
- 允许不同世界对相同物理内存使用不同的虚拟映射

## 4. 关键系统寄存器

### GPC 配置寄存器

| 寄存器 | 用途 | 访问级别 | ARM 手册参考 |
|----------|---------|--------------|---------------------|
| **GPCCR_EL3** | GPC 使能、GPT 大小/颗粒配置 | 仅 EL3 | D24.2.50（第 7559 页） |
| **GPTBR_EL3** | GPT 表物理基地址 | 仅 EL3 | D24.2.51（第 7566 页） |

### GPCCR_EL3 关键字段
- **GPC_EN**：全局 GPC 使能/禁用
- **GPT_SIZE**：GPT 表大小配置
- **GPT_PGS**：颗粒大小（通常 4KB）
- **GPT_NS/S/R**：世界特定 GPT 配置

### 其他相关寄存器

| 寄存器 | 用途 | 与 CCA 的相关性 |
|----------|---------|------------------|
| **MECID_RL_A_EL3** | Realm PA 空间加密上下文 | 内存加密上下文 |
| **SPMROOTCR_EL3** | Root/Realm 性能监视器控制 | 防止信息泄露 |
| **SCR_EL3** | 安全配置寄存器 | 世界转换控制 |
| **HCR_EL2** | 虚拟机监控器配置寄存器 | 虚拟化陷入控制 |

## 5. 在 TF-A / SPM 中的实现

### 传统 SPM 架构

```
┌─────────────────────────────────────┐
│            EL3 (Monitor)            │
│  ┌─────────────────────────────┐    │
│  │      SPM (TF-A)             │    │
│  │  • 安全分区管理              │    │
│  │  • SMC 处理                 │    │
│  │  • 上下文切换               │    │
│  └──────────────┬──────────────┘    │
└─────────────────┼────────────────────┘
                  │
          ┌───────┴───────┐
          ▼               ▼
     安全分区
```

### CCA 增强架构（RMM）

```
┌─────────────────────────────────────────────────────┐
│                 EL3 (Root 世界)                     │
│  ┌─────────────────────────────────────────────┐    │
│  │     增强型 SPM / 领域管理器 (RMM)           │    │
│  │  • Secure + Realm 分区管理                  │    │
│  │  • GPT/GPC 配置                             │    │
│  │  • 世界生命周期管理                          │    │
│  └──────────────────┬──────────────────────────┘    │
└─────────────────────┼───────────────────────────────┘
        ┌─────────────┼─────────────┐
        ▼             ▼             ▼
  Secure 世界    Realm 世界    Non-secure 世界
  分区           分区
```

### Realm 分区创建流程

```c
// 1. 内存分配和 GPT 配置
realm_mem = allocate_physical_memory(size);
for (每个 4KB 颗粒) {
    set_gpt_entry(granule_pa, GPI_REALM_ONLY);
}

// 2. Realm 转换表
realm_ttbr0 = create_realm_translation_tables(realm_mem, size);
setup_realm_mair_el1();
setup_realm_tcr_el1();

// 3. 上下文初始化
init_realm_context(&ctx);
ctx.ttbr0_el1 = realm_ttbr0;
ctx.elr_el1 = entry_point;

// 4. 世界切换配置
scr_el3 = read_scr_el3();
scr_el3.ns = 0;  // 非 Non-secure
scr_el3.rw = 1;  // AArch64

// 5. 切换到 Realm
switch_to_realm(&ctx);
```

### 关键 TF-A 组件

- **SPM 核心**：`services/std_svc/spm/`
- **上下文管理**：`lib/el3_runtime/context_mgmt*`
- **RME 支持**：`include/lib/extensions/feat_rme.h`
- **Realm 管理**：`services/std_svc/rmmd/`（新兴）

## 6. 安全优势

### 1. 硬件强制隔离
- **颗粒级别**：4KB 粒度 vs 传统页面级别
- **物理地址级别**：独立于虚拟映射
- **DMA 保护**：包括外设 DMA 访问
- **防篡改**：GPT 由 Root 控制，硬件强制执行

### 2. 减少可信计算基（TCB）
```
传统：应用 → OS → 虚拟机监控器 → 固件 → 硬件
                 │       │           │           │
                 └───────┴───────────┴───────────┘
                     数百万行代码

CCA Realm：Realm 工作负载 → 硬件 + Root 固件
                 │                    │
                 └────────────────────┘
                   < 10 万行代码
```

### 3. 攻击抵抗
- **软件攻击**：与 OS/虚拟机监控器漏洞隔离
- **侧信道攻击**：硬件隔离减少时序信道
- **物理攻击**：可选内存加密（MEC 扩展）
- **DMA 攻击**：硬件强制防止未经授权的 DMA

### 4. 性能效率
- **硬件加速**：内存控制器中的 GPC 检查
- **减少陷入**：与虚拟机监控器相比更少的世界切换
- **并行操作**：GPC 查找与缓存访问并发
- **研究显示**：敏感工作负载性能提升 5-15%

## 7. 应用场景

### 1. 机密云计算
- **问题**：云租户不信任提供商的软件栈
- **解决方案**：租户 VM 在 Realm 世界中运行
- **用例**：
  - 金融数据处理
  - 医疗健康分析（HIPAA 合规）
  - 多租户隔离
- **示例**：Azure 机密计算、Google 机密 VM

### 2. 多方安全计算
- **问题**：多个组织需要联合计算而不暴露个体数据
- **解决方案**：各方的代码在单独的 Realm 中运行
- **用例**：
  - 联邦学习
  - 隐私保护分析
  - 敏感数据的安全协作
- **技术契合**：补充同态加密

### 3. 数字版权管理
- **问题**：保护优质内容免受盗版
- **解决方案**：在 Realm 中进行内容解密/渲染
- **用例**：
  - 4K/8K 视频流
  - DRM 保护的游戏
  - 企业软件许可
- **优势**：比传统 TEE 更小的攻击面

### 4. 安全服务隔离
- **问题**：TEE 中的安全服务共享攻击面
- **解决方案**：将服务隔离到单独的 Realm
- **用例**：
  - 加密服务隔离
  - 生物识别认证
  - 安全存储服务
- **好处**：遏制泄露

### 5. 边缘计算与物联网
- **问题**：在不可信环境中处理敏感数据
- **解决方案**：在 Realm 中进行本地处理
- **用例**：
  - 智能摄像头视频处理
  - 工业物联网算法保护
  - 医疗设备数据处理

## 8. 与传统虚拟化对比

### 全面对比表

| 方面 | 传统虚拟化（EL2） | CCA Realm |
|--------|----------------------------------|-----------|
| **隔离** | 软件（虚拟机监控器） | 硬件（GPC） |
| **信任模型** | VM 信任虚拟机监控器（大 TCB） | Realm 信任硬件 + Root（小 TCB） |
| **性能** | 高开销（陷入、模拟） | 硬件加速 |
| **攻击面** | 数百万行代码（虚拟机监控器） | 数万行代码（Root 固件） |
| **内存保护** | 页面级别，软件管理 | 颗粒级别，硬件强制 |
| **DMA 保护** | 需要 IOMMU/SMMU | 内置 GPC |
| **兼容性** | 未修改的客户机 OS | 需要 Realm 感知软件 |
| **实时迁移** | 支持 | 复杂（硬件绑定） |
| **管理** | 成熟（libvirt、OpenStack） | 新兴框架 |
| **最适合** | 通用整合 | 机密计算 |

## 9. 技术实施考虑

### 内存开销
- **GPT 大小**：约占物理内存的 ~0.024%
- **示例**：1TB RAM 需要约 256MB 用于 GPT
- **缓存效率**：GPC TLB 减少查找开销

### 性能影响
- **延迟**：GPC 检查增加最小开销（与缓存访问并行）
- **吞吐量**：批量操作的硬件优化
- **功耗**：GPC 检查的额外硬件

### 软件要求
- **Root 固件**：支持 RME 的 TF-A
- **客户机软件**：Realm 感知的操作系统
- **管理**：Realm 生命周期管理的新工具
- **开发**：新 SDK 和框架

### 迁移路径
1. **阶段 1**：硬件可用性（支持 RME 的芯片）
2. **阶段 2**：固件支持（TF-A 更新）
3. **阶段 3**：操作系统支持（Linux、Windows Realm 模式）
4. **阶段 4**：应用生态系统开发
5. **阶段 5**：成熟的工具和管理

## 12. 结论

ARM CCA 代表了计算安全的范式转变，从基于软件的信任模型转向硬件根植的信任模型。具有颗粒保护检查的四世界架构提供：

1. **前所未有的隔离**：硬件强制在 4KB 粒度
2. **最小信任基**：Realm 工作负载仅信任硬件 + 固件
3. **云就绪安全**：实现真正的机密云计算
4. **性能效率**：硬件加速保持性能
5. **演进路径**：与现有生态系统向后兼容

随着技术的成熟，CCA 有可能成为安全领域的变革性技术，就像虚拟化对服务器整合的变革一样，使新一代应用程序能够在不可信环境中安全运行，同时保护数据机密性和知识产权。
