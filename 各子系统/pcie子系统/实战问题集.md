## 案例机制归类（按层）

### 1. 静默写 0x0 -- 译码层（未使能期的"黑洞写入"）

```
Cadence IP 默认基地址未初始化（全 0）
  -> 设备 DMA/Message 写 "地址 0x0"
  -> RC 把它译码到 DDR 物理起始处 = 内核关键内存
  -> 随机内存损坏，现象与触发时机无关（最难查的一类）
```

修复模式：DTS 为每个 RC 预留 4KB "牺牲页"（安全地址 0x0 附近）兜住误写 + 修初始化序列。

通用启示：**先于软件初始化的硬件默认态是 bringup 最大风险源**；地址 0 的写入永远不该落到真实内存。

### 2. PME_Turn_Off -- 协议序列层

见 [电源管理与链路状态](./电源管理与链路状态.md) 第 2 节。要点：消息码配错（0x15 vs 0x19）设备侧不认，握手不完成，链路卡过渡态。修复三件套：协议修正 + 状态轮询确认 + 中断 quiesce。

### 3. 降级模式 -- 控制器配置层

见 [性能调优](./性能调优.md)。要点：`LnkSta` 正常但控制器内部功能被固件 disable 残留；标准寄存器看不到，只能对照实验 + 固件 diff。

### 4. Alignment Fault -- CPU 架构层

见链接笔记。要点：BAR 经 ioremap 是 Device nGnRE，Arm64 禁止非对齐访问；`__packed` 结构 + readq = 必炸；用 `ioread64_lo_hi` 显式拆分。

## 案例之外的通用排查清单（bringup 板凳图）

```
物理层   PERST# / refclk / LTSSM 到 L0？
配置层   ECAM 通？lspci 可见？
译码层   BAR 探到合理大小？父桥窗口开好？（案例1）
驱动层   Bus Master？MSI Table 写好？（MSI 笔记）
架构层   访问宽度/对齐/内存类型合规？（案例4）
电源层   suspend/resume 序列完整？（案例2/电源笔记）
性能层   速率宽度 MPS/MRRS？（案例3）
```

自底向上逐层 pass，是所有 PCIe 问题的统一排查框架。
