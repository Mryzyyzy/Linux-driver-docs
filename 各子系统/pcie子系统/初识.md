### 1. PCIe 协议分层与 TLP

PCIe 是**串行点到点**总线，数据以 **TLP（Transaction Layer Packet）** 为单位传输：

```
应用层（设备驱动）
  │ 读写 BAR 空间、DMA
  ▼
事务层（Transaction Layer）
  │ 组装 TLP：Header + Data + ECRC
  │ TLP 类型：Memory Read/Write、IO Read/Write、Config Read/Write、Message
  ▼
数据链路层（Data Link Layer）
  │ ACK/NAK、流控、LCRC
  ▼
物理层（Physical Layer）
  │ 8b/10b 编码(Gen1/2) / 128b/130b(Gen3+)、LTSSM 链路训练
  ▼
差分线对（Tx/Rx，lane 数：x1/x2/x4/x8/x16）
```

**几个关键概念**：

- **BDF（Bus:Device:Function）**：PCIe 设备的编址方式，每个 Function 有独立的配置空间
- **BAR（Base Address Register）**：配置空间中的寄存器，声明设备需要的 MMIO/IO 地址空间大小，BIOS/OS 分配地址后写回
- **配置空间**：256B（常规）/ 4KB（ECAM 扩展），通过 ECAM（Enhanced Configuration Access Mechanism）MMIO 方式访问
- **MSI/MSI-X**：消息信号中断，设备写一个特定地址触发中断，替代传统 INTx 线中断
- **ATS/PRI/PASID**：PCIe 高级特性，和 SMMU/IOMMU 配合实现设备侧地址翻译

### 2. ARM64 平台 PCIe 的特殊性

和 x86 相比，ARM64 上的 PCIe 有几个本质差异：

|对比项|x86|ARM64|
|---|---|---|
|配置空间访问|`outl`/`inl` 指令 + MCFG（ECAM）|纯 MMIO（ECAM）|
|IO 空间|`inb`/`outb` 指令，64KB IO 地址空间|通过 PCIe RC 映射到 MMIO，再模拟 IO 访问|
|中断|8259 → IOAPIC → MSI|GICv3 ITS（Interrupt Translation Service）|
|总线枚举|BIOS/UEFI 做完整枚举|UEFI 或 Kernel 做枚举；DT 描述 RC 节点|
|DMA 一致性|硬件一致性（cache coherent）|依赖 IP 设计，CIX 平台有 ACIFY 做一致性|
|Root Complex|集成在北桥/PCH|集成在 SoC 内，CIX 用 Cadence PCIe IP|

**CIX Sky1 的 PCIe 架构**：

- 用 **Cadence PCIe Controller IP** 作为 Root Complex
- PCIe 一侧是标准协议，另一侧接 **AXI 总线**（ARM SoC 内部总线）
- `drivers/pci/controller/cadence/pci-sky1.c` 是 CIX 定制的驱动
- 有多个 PCIe 端口（X4 slot、X8 slot 等）
- RTL8125 2.5GbE 网卡挂在 PCIe 总线上（BDF `0001:21:00.0` → 接口名 `enP1p33s0`）

### 3. PCIe 与 SMMU 的交互

这是 Xen bringup 中一个核心交互点：

```
PCIe 设备发起 DMA
  │
  ▼
SMMU（IOMMU）
  │ 查 Stream Table（按 StreamID 索引）
  │ StreamID 来自 PCIe 的 Requester ID = BDF
  ▼
Stage-1/Stage-2 地址翻译
  │
  ▼
物理内存
```

- **StreamID 映射**：PCIe BDF → SMMU StreamID 的关系在 DTB 中通过 `iommu-map` 属性描述
- **ATS（Address Translation Service）**：PCIe 设备可以请求 SMMU 翻译并缓存翻译结果（设备侧 TLB，叫 ATC）
- **PRI（Page Request Interface）**：设备遇到 translation fault 时主动发 page request，OS 填好页表后回复

在 Xen 环境下，PCIe passthrough 需要：

1. 设备的 MMIO BAR 映射到 Dom0/DomU 的 stage-2 页表
2. 设备的中断（MSI/MSI-X）路由到对应 domain
3. SMMU 中为该设备的 StreamID 配置正确的 STE（Stream Table Entry），指向对应 domain 的 IPA→PA 翻译

### 4. PCIe 枚举与驱动加载流程

```
pci_acpi_scan_root() / of_pci_init()
  │  从 ACPI _DSM 或 DT 读取 RC 信息：ECAM 基址、IO/MMIO 窗口、中断映射
  ▼
pci_scan_root_bus()
  │  遍历 bus 0~255，每个 bus 扫 device 0~31，每个 device 扫 function 0~7
  │  读 Vendor ID / Device ID，识别设备
  ▼
pci_assign_unassigned_resources()
  │  分配 BAR 地址（MMIO/IO 窗口内）
  ▼
pci_bus_add_devices()
  │  注册到 driver core，触发 driver match
  ▼
pci_driver.probe()   ← 设备驱动入口
  │  pci_enable_device() → 开 MMIO/IO/Bus Master
  │  pci_iomap() → 映射 BAR 到虚拟地址
  │  申请中断（pci_alloc_irq_vectors → MSI-X/MSI/INTx）
  ▼
设备就绪
```

**在 Xen Dom0 中的差异**：

- PCIe RC 直通给 Dom0，Dom0 正常枚举，大部分驱动无感
- 但 ECAM 配置空间的地址范围必须映射到 Dom0 P2M
- MSI 中断需要 Xen 正确路由（通过 GIC/VGIC）
- 如果设备要做 passthrough 给 DomU，还需要 VFIO + Xen pciback 做接管
