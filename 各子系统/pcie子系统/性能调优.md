# PCIe 性能调优

> 带宽账、MPS/MRRS、降级检测、交叉验证方法论。项目实例（2.9 -> 6.3GB/s，113%）详见 [PCIe性能调优-113](../../../07_面试/简历打磨/知识点/PCIe性能调优-113.md)。代码摘自本地内核树 6.12.58。

## 1. 带宽理论账（先会算再看问题）

| Gen | 单 lane 速率 | 128b/130b 后有效 | x8 单向有效 |
|---|---|---|---|
| Gen3 | 8GT/s | ~7.88Gb/s | ~7.88GB/s |
| **Gen4** | 16GT/s | ~15.75Gb/s | **~15.75GB/s** |
| Gen5 | 32GT/s | ~31.5Gb/s | ~31.5GB/s |

- 实测达不到理论值：TLP 开销（header/ECRC/digest）、流控回包（Ack）、应用层 round-trip（NVMe 队列深度）
- NVMe 顺序读 x8 Gen4 实测上限 6-7GB/s（受盘端与协议栈限制，不是 PCIe 瓶颈）

## 2. 三个可调参数

### MPS / MRRS（源码摘录）

```c
/* drivers/pci/probe.c（PCIE_BUS_PERFORMANCE 策略下自动配 MRRS） */
	mrrs = pcie_get_mps(dev);

	/*
	 * MRRS is a R/W register.  Invalid values can be written, but a
	 * subsequent read will verify if the value is acceptable or not.
	 * If the MRRS value provided is not acceptable (e.g., too large),
	 * shrink the value until it is acceptable to the HW.
	 */
	while (mrrs != pcie_get_readrq(dev) && mrrs >= 128) {
		rc = pcie_set_readrq(dev, mrrs);
		if (!rc)
			break;
```

| 参数 | 含义 | 影响 |
|---|---|---|
| **MPS**（Max Payload Size） | 一个 TLP 最大载荷 | 吞吐主参数；全链路取 RC/桥/设备的最小值 |
| **MRRS**（Max Read Request Size） | 一次读请求最大长度 | 读性能主参数；只能 ≤ MPS 且不超过上游能力 |
| Read prefetch | 控制器投机读 | 随机负载关、顺序负载开 |

- 内核策略：`pcie_bus_config`（`pcie_bus_perf` 内核参数）驱动；安全模式 MPS=128（慢但稳）
- 调优顺序：**先确认链路速率/宽度没降级，再动 MPS/MRRS**--参数救不了物理层

## 3. 排查方法论：12 轮交叉验证（项目实战）

排除法框架，每轮只动一个变量：

```
换盘不涨   -> 排除 SSD 自身
换槽不涨   -> 排除该 slot 走线/时钟
换板涨了   -> 锁定板级/固件差异 -> diff 两板固件初始化路径
回溯 UEFI  -> 发现 x8 slot 在 UEFI 阶段被 disable，控制器进降级模式
              （LnkSta 正常但内部预取/流水线关闭 -> 带宽近似减半）
```

- 每轮记录：`lspci -vv`（LnkCap/LnkSta/Express 控制寄存器）、fio 参数与结果
- **核心教训：链路状态寄存器正常 ≠ 控制器完整工作状态**；bringup 级问题要看控制器模式寄存器与固件初始化残留

## 4. 常见性能杀手清单

| 杀手 | 特征 | 检测/修复 |
|---|---|---|
| 链路降速降宽 | LnkSta < LnkCap | `lspci -vv`；查训练/信号/固件残留 disable |
| MPS/MRRS 保守 | 吞吐约降 20-40% | setpci / `pcie_bus_perf` |
| 中断单核打满 | 单 CPU 100% 且带宽上不去 | `PCI_IRQ_AFFINITY` 多队列+亲和分散 |
| IOMMU 翻译开销 | 高 IOPS 下延迟高 | ATS/PRI、大页映射（SMMU 2M/1G 页） |
| 读写混流死锁式退避 | 读饥饿 | 流控调参、队列调度 |
| ASPM L1 频繁进出 | 低负载延迟毛刺 | `pcie_aspm=performance` 对照定位 |

## 6. 面试问答

**Q: MPS 和 MRRS 为什么分开存在？**
MPS 限单个 TLP 载荷（缓冲区大小决定）；MRRS 限"一次读请求"大小（读请求无数据载荷，但触发对端回包规划），MRRS 可以大于 MPS 提升读吞吐但不能超过上游 MPS 能力。

**Q: 带宽只有理论一半，排查顺序？**
一看 LnkSta 是否降速/降宽；二看 MPS/MRRS；三看中断是否单核瓶颈；四看是否 IOMMU 翻译开销；最后才怀疑固件级控制器模式（需要对照实验或寄存器 dump）。

**Q: 为什么你那个案例 lspci 看不出问题？**
UEFI 残留的是控制器内部工作模式（预取/流水线类功能开关），不在标准 Capability 里，LTSSM 与链路状态位都正常--只有带宽对照和固件 diff 能暴露。

**Q: x8 Gen4 用 4KB 随机读为什么只有几百 MB/s？**
随机读是 IOPS 型负载，瓶颈在 NVMe 命令处理往返而不是链路带宽；带宽参数（MRRS）几乎无感，应调队列深度与中断亲和。
