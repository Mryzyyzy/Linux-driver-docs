# PCIe 枚举与资源分配

> 承接 [初识.md](./初识.md) 的枚举流程图，本文下钻到代码级：ECAM 怎么访问、BAR 怎么探大小、资源怎么分。代码摘自本地内核树 6.12.58（`drivers/pci/probe.c`、`drivers/pci/setup-bus.c`）。

## 1. 配置空间访问：ECAM

```
ECAM 基址（DT: reg = <0x0 0xe0000000 0x0 0x1000000>）
  + (Bus << 20) | (Device << 15) | (Function << 12) | offset
```

- 每个_function_占 4KB 窗口，256B 常规配置空间 + PCIe 扩展 capabilities（4KB 内）
- 内核侧 `pci_generic_config_read/write` -> `bus->ops->read`，arm64 上即 ECAM MMIO 读写
- bringup 首验：`lspci` 能否列出设备。列不出 -> 查 ECAM 窗口 DT、LTSSM 是否 L0、clock/reset

## 2. LTSSM：链路训练状态机

```
Detect -> Polling -> Configuration -> Recovery -> L0（正常工作）
                                        │
                                L0s / L1（ASPM 低功耗）<-> L0
                                        │
                              L2/L3（链路下电，唤醒走 Recovery）
```

- 训练内容：bit lock、lane 极性/序号重排、协商宽度（x8 会降到 x1/x2/x4）与速率（Gen1 起步，后续升 Gen3/4/5）
- **降速降宽自动发生**：信号质量差训练不上去就窄化--`lspci -vv` 看 `LnkSta`（当前）vs `LnkCap`（能力），不一致就是降级
- 环回/示波器眼图是物理层验收手段；软件层先看 LSTA 状态寄存器

## 3. BAR 探测：写全 1 再读回（源码摘录）

```c
/* drivers/pci/probe.c */
int __pci_read_base(struct pci_dev *dev, enum pci_bar_type type,
		    struct resource *res, unsigned int pos)
{
	u32 l = 0, sz = 0, mask;
	...
	/* No printks while decoding is disabled! */
	if (!dev->mmio_always_on) {
		pci_read_config_word(dev, PCI_COMMAND, &orig_cmd);
		if (orig_cmd & PCI_COMMAND_DECODE_ENABLE) {
			pci_write_config_word(dev, PCI_COMMAND,
				orig_cmd & ~PCI_COMMAND_DECODE_ENABLE);
		}
	}
	...
	pci_read_config_dword(dev, pos, &l);
	/* 后续：往 BAR 写全 1（sz = ~0），读回后低有效位为 0 的部分就是"硬连线的大小位" */
```

要点（面试）：
- **BAR sizing = 写全 1 读回**：读回值最低位 0 连到多少位，就是硬件声明的最小地址粒度（2^n 大小）；bit0=0 表示 MMIO、bit1..2=类型（32bit/64bit/可预取）、bit3=可预取
- 探测期间**先关 memory decode**（防误译码写脏内存--与简历"静默写 0x0 内存损坏"问题同一风险域）
- 64bit BAR 占两个连续寄存器
- 大小 2^n 对齐是规格要求；读到奇怪大小 = BAR 寄存器状态被固件动过或读回了 0xFFFFFFFF（设备不响应）

## 4. 资源分配：`pci_assign_unassigned_resources`

```
每个 bridge 有 IO/Mem/Prefetch 三组窗口（base/limit）
分配 = 递归求解：叶子设备 BAR 窗口装进父桥窗口，逐级向上收口
```

- 窗口必须自然对齐且不能重叠；空间不够时内核放弃分配（dmesg "not enough window space"）
- 可预取（Prefetchable）BAR 单独一类，允许合并映射成写合并（write-combining）
- `lspci -vv` 的 `Memory behind bridge` 就是父桥窗口；排资源冲突时从叶子往根画一张窗口图最快

## 5. 驱动绑定与标准 probe 序列

```c
/* include/linux/pci.h */
struct pci_driver {
	const char		*name;
	const struct pci_device_id *id_table;	/* Must be non-NULL for probe to be called */
	int  (*probe)(struct pci_dev *dev, const struct pci_device_id *id);
	void (*remove)(struct pci_dev *dev);
	int  (*suspend)(struct pci_dev *dev, pm_message_t state);
	int  (*resume)(struct pci_dev *dev);
	...
};
```

probe 标准动作：

```c
pci_enable_device(dev);            /* 开 MEM/IO decode + Bus Master（DMA 必需！） */
pcim_ioremap_regions(dev, BIT(bar));/* 映射 BAR（devm 化） */
pci_alloc_irq_vectors(dev, 1, N, PCI_IRQ_MSIX | PCI_IRQ_MSI);
pci_set_master(dev);               /* 单独使能 Bus Master */
```

**忘 `pci_set_master` = 设备 DMA 发不出**（经典 bringup 坑：驱动 probe 成功但收不到数据）。

## 6. 调试速查

| 现象 | 首查 |
|---|---|
| lspci 无设备 | ECAM 窗口 / LTSSM 是否 L0 / PERST# 时序 |
| `lspci -vv` 显示 `LnkSta: x1 2.5GT/s` 而 `LnkCap: x8 16GT/s` | 训练降级：信号/时钟/refclk 极性，或固件残留降级模式（见 [性能调优](./性能调优.md)） |
| BAR 全 F | 设备配置 TLP 无响应：上游桥窗口没开、ADR_COMPLETE 超时 |
| 驱动 probe 后设备无响应 | Bus Master 没开 / BAR 映射错 bar 号 |
| dmesg `BAR N: can't assign` | 父桥窗口不够，查 DT ranges 与分配日志 |
