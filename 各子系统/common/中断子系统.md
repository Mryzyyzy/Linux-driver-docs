# 中断子系统（IRQ 框架）

> 通用 IRQ 框架视角（irq_desc/irq_domain/线程化中断）；GIC 硬件级细节见 [[GIC中断总览]] 对应目录。代码摘自本地内核树 6.12.58。

## 1. 全景分层

```
设备驱动        request_irq() / devm_request_threaded_irq()
                     │ virq（虚拟中断号）
通用 IRQ 核心   kernel/irq/manage.c   中断申请/使能/亲和性
                kernel/irq/chip.c     irq_chip 操作、handle_* 流控
                kernel/irq/irqdomain.c  hwirq <-> virq 翻译
                     │
irq_chip 驱动   irq-gic-v3.c / irq-mst-virt-eic...   硬件中断控制器
                     │
异常入口        arch/arm64/kernel/entry.S -> handle_arch_irq -> gic_handle_irq
```

三个关键编号概念（面试必考）：

| 编号                     | 谁定义          | 例子                            |
| ---------------------- | ------------ | ----------------------------- |
| **hwirq**              | 中断控制器硬件规格    | GICv3 的 INTID（SPI 从 32 起）     |
| **virq**               | Linux 内核软件分配 | `/proc/interrupts` 里看到的号      |
| **irq_data hierarchy** | 级联时每级一个      | MSI: msi_domain -> gic_domain |
|                        |              |                               |

## 2. 核心结构与 API（源码摘录）

### 申请中断：request_irq 就是 request_threaded_irq 的马甲

```c
/* include/linux/interrupt.h */
extern int __must_check
request_threaded_irq(unsigned int irq, irq_handler_t handler,
		     irq_handler_t thread_fn,
		     unsigned long flags, const char *name, void *dev);

static inline int __must_check
request_irq(unsigned int irq, irq_handler_t handler, unsigned long flags,
	    const char *name, void *dev)
{
	return request_threaded_irq(irq, handler, NULL, flags | IRQF_COND_ONESHOT, name, dev);
}
```

- `handler`：硬中断上下文（top half），返回 `IRQ_WAKE_THREAD` 才唤醒线程
- `thread_fn`：内核线程上下文（bottom half），可睡眠
- 关键 flags：`IRQF_SHARED`（共享线，必须 dev 可区分）、`IRQF_TRIGGER_*`（边沿/电平）、`IRQF_ONESHOT`（线程执行期间屏蔽该线，防重复触发）

### `struct irq_domain_ops` - hwirq->virq 的翻译层

```c
/* include/linux/irqdomain.h */
struct irq_domain_ops {
	int (*match)(struct irq_domain *d, struct device_node *node, ...);
	int (*select)(struct irq_domain *d, struct irq_fwspec *fwspec, ...);
	int (*map)(struct irq_domain *d, unsigned int virq, irq_hw_number_t hw);
	void (*unmap)(struct irq_domain *d, unsigned int virq);
	int (*xlate)(struct irq_domain *d, struct device_node *node,
		     const u32 *intspec, unsigned int intsize,
		     unsigned long *out_hwirq, unsigned int *out_type);
	/* 层级域（GICv3/MSI 用） */
	int (*alloc)(struct irq_domain *d, unsigned int virq,
		     unsigned int nr_irqs, void *arg);
	int (*activate)(struct irq_domain *d, struct irq_data *irqd, bool reserve);
	int (*translate)(struct irq_domain *d, struct irq_fwspec *fwspec, ...);
};
```

- **xlate**：解析 DT 的 `interrupts` 元组（GIC: `<GIC_SPI 123 IRQ_TYPE_LEVEL_HIGH>` -> hwirq=155, type=LEVEL）
- **层级域**：MSI/中断级联场景，alloc/activate 沿层级下发（`irq_domain_alloc_irqs_parent`），每一级挂自己的 irq_chip

### 数据结构关系

```
irq_desc (virq)  ── irq_data 链（级联时 domain 链）──> irq_chip（enable/unmask/ack）
      │
      ├── action 链表（共享中断多个 handler）
      └── handle_irq 流控函数：
           handle_level_irq   电平：mask+ack -> handler -> unmask
           handle_edge_irq    边沿：ack，处理中再来要记录 pending
           handle_fasteoi_irq GICv3 LPI 常用：结束时统一 EOI
```

## 3. 中断处理全链路（arm64）

```
外设电平变化 -> GIC (IRQ line) -> CPU IRQ 异常
  -> entry.S vector -> el1_irq -> handle_arch_irq (gic_handle_irq)
  -> gic_read_iar (ACK+取INTID) -> generic_handle_irq(virq)
  -> desc->handle_irq (流控) -> handle_irq_event
  -> action->handler (top half)          # 不能睡眠！
       └─ 返回 IRQ_WAKE_THREAD -> 唤醒 irq/N-thread 线程 -> thread_fn
  -> gic_eoi_irq
```

读点：
- **GIC 的 ACK 在链路最前**（IAR 读），**EOI 在最后**--中间是完整处理窗口
- top half 只做"取数据 + 判定是否唤醒线程"，其余都推给 thread_fn / softirq / workqueue

## 4. bottom half 三选一

| 机制 | 上下文 | 可睡眠 | 典型用途 |
|---|---|---|---|
| threaded_irq | 内核线程 | ✅ | 外设驱动主力（I2C 传感器中断后走 I2C 读数据，必须可睡眠） |
| tasklet/softirq | 软中断上下文 | ❌ | 网络收包、块层（新代码别用 tasklet） |
| workqueue | 进程上下文 | ✅ | 大工作量、可能睡眠、需要调度优先级 |

## 5. 调试

| 手段 | 用法 |
|---|---|
| `/proc/interrupts` | 每 virq 计数、亲和性、驱动名（计数不涨=中断没到） |
| `/proc/irq/<virq>/` | 亲和性设置、spurious 统计 |
| `/sys/kernel/debug/irq_domain_mapping` | hwirq<->virq 映射全表 |
| ftrace | `irq_handler_entry/exit`、`irq_thread_entry` |
| 现象速查 | 计数狂涨=流控没 ack/mask；一次就停=EOI 时机错；共享线上 NULL dev=devm 双重释放 |

## 6. 面试问答

**Q: request_irq 和 request_threaded_irq？**
request_irq 是 threaded 版的 handler-only 马甲（见源码）。handler 跑在硬中断上下文禁睡眠；重活放 thread_fn。

**Q: IRQF_ONESHOT 什么时候必须？**
threaded 且 handler 为空（或需要整段处理期间屏蔽线）时必须，否则线程还没跑、中断又来，会打爆。GIC 电平中断尤其需要。

**Q: 共享中断怎么区分归属？**
IRQF_SHARED + 各自 dev 指针；handler 里先查自己硬件的 pending 位，不是自己的返回 IRQ_NONE。全 NONE 会被内核记 spurious 并最终禁掉该线。

**Q: irq_domain 为什么存在？**
hwirq 与 virq 解耦：级联/MSI/虚拟化场景多层翻译，DT 描述是硬件相关的元组，xlate 统一转成 virq 分配与 chip 挂接。

**Q: 边沿 vs 电平处理的差别？**
边沿不 mask（错过就丢，处理中再来到 pending 位补投递）；电平必须先 mask（不 mask 会一直触发），处理完 unmask。
