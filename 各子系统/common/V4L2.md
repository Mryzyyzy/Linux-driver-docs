# V4L2 子系统（Video4Linux2）

以 Linux 6.12（`drivers/media/v4l2-core/` + `include/media/`）源码为例整理。代码摘自本地内核树 `cix_6.12_master_Dev/linux`，示例传感器 imx219。智驾相机 bringup（GMSL SerDes + 传感器）的全部框架知识都在这篇。

## 1. 全景分层

```
用户态        v4l2-ctl / libcamera / 厂商中间件
                  │ ioctl: VIDIOC_*
字符设备层    video_device (/dev/video0..N)  + v4l2_fops
                  │
V4L2 核心     v4l2-device / v4l2-dev / v4l2-ioctl / v4l2-ctrls / v4l2-subdev
                  │
异构组件      ┌─ v4l2_subdev：传感器（I2C）、SerDes 桥（MAX96717/96724）都是 subdev
              ├─ vb2 (videobuf2)：缓冲区管理（分配/入队/出队/DMA）
              └─ media controller：把 subdev/桥/采集节点连成 pipeline 拓扑
```

关键认知：**一根视频链路上的每个芯片（传感器、串行器、解串器、CSI receiver、ISP）在内核里都是一个 v4l2_subdev**，media graph 把它们串起来；`/dev/videoN` 只是 pipeline 的出口节点。

## 2. 核心结构（源码摘录，6.12.58）

### `struct v4l2_subdev_ops` - subdev 的回调集

```c
/* include/media/v4l2-subdev.h */
struct v4l2_subdev_ops {
	const struct v4l2_subdev_core_ops	*core;    /* load_fw, reset, ioctl 杂项 */
	const struct v4l2_subdev_tuner_ops	*tuner;
	const struct v4l2_subdev_audio_ops	*audio;
	const struct v4l2_subdev_video_ops	*video;   /* s_stream 等 */
	const struct v4l2_subdev_vbi_ops	*vbi;
	const struct v4l2_subdev_ir_ops		*ir;
	const struct v4l2_subdev_sensor_ops	*sensor;
	const struct v4l2_subdev_pad_ops	*pad;     /* set_fmt/get_fmt, enable_streams */
};
```

- 面试口径：**core 管杂项、video 管（旧式）流开关、pad 管格式协商**；新内核推 `pad.enable_streams` 取代 `video.s_stream`
- 传感器驱动（如 imx219）probe 里一行接入：

```c
/* drivers/media/i2c/imx219.c */
static int imx219_probe(struct i2c_client *client)
{
	...
	v4l2_i2c_subdev_init(&imx219->sd, client, &imx219_subdev_ops);
	...
}
```

`v4l2_i2c_subdev_init` 把 I2C client 包成 subdev，此后框架内的调用（set_fmt/s_stream）最终变成对它的 I2C 寄存器读写。

### `struct v4l2_file_operations` - /dev/videoN 的文件操作

```c
/* include/media/v4l2-dev.h */
struct v4l2_file_operations {
	struct module *owner;
	ssize_t (*read) (struct file *, char __user *, size_t, loff_t *);
	__poll_t (*poll) (struct file *, struct poll_table_struct *);
	long (*unlocked_ioctl) (struct file *, unsigned int, unsigned long);
	unsigned long (*get_unmapped_area) (...);
	int (*mmap) (struct file *, struct vm_area_struct *);
	int (*open) (struct file *);
	int (*release) (struct file *);
};
```

- 绝大多数驱动用 `vb2_fops`（videobuf2 提供的通用实现），mmap/ioctl 全部接好

### `struct vb2_ops` - 缓冲队列驱动回调

```c
/* include/media/videobuf2-core.h */
struct vb2_ops {
	int (*queue_setup)(struct vb2_queue *q,
			   unsigned int *num_buffers, unsigned int *num_planes,
			   unsigned int sizes[], struct device *alloc_devs[]);
	void (*wait_prepare)(struct vb2_queue *q);
	void (*wait_finish)(struct vb2_queue *q);
	int (*buf_out_validate)(struct vb2_buffer *vb);
	int (*buf_init)(struct vb2_buffer *vb);
	int (*buf_prepare)(struct vb2_buffer *vb);
	void (*buf_finish)(struct vb2_buffer *vb);
	void (*buf_cleanup)(struct vb2_buffer *vb);
	int (*prepare_streaming)(struct vb2_queue *q);
	int (*start_streaming)(struct vb2_queue *q, unsigned int count);
	void (*stop_streaming)(struct vb2_queue *q);
	void (*unprepare_streaming)(struct vb2_queue *q);
	void (*buf_queue)(struct vb2_buffer *vb);
	void (*buf_request_complete)(struct vb2_buffer *vb);
};
```

- `queue_setup`：用户 REQBUFS 时被调，决定 buffer 数量/平面大小/分配设备（DMA-BUF heap 就在这接）
- `start_streaming`：真正点链路（传感器 s_stream -> CSI -> DMA 使能）
- `buf_queue`：buffer 入队时挂到驱动的 ready 队列，等硬件填充

## 3. v4l2-async：组件绑定的胶水（bringup 核心）

传感器和桥是分开 probe 的（I2C 总线先后不定），用异步绑定把它们凑齐：

```c
/* include/media/v4l2-async.h */
enum v4l2_async_match_type {
	V4L2_ASYNC_MATCH_TYPE_I2C,     /* 按 i2c 地址+总线匹配（旧式） */
	V4L2_ASYNC_MATCH_TYPE_FWNODE,  /* 按设备树 endpoint 的 fwnode 匹配（主流） */
};
```

绑定流程（智驾平台实际路径）：
1. 采集节点驱动（CSI/ISP）probe：解析 DT 的 ports/endpoints，注册 `v4l2_async_notifier`
2. 传感器/SerDes subdev probe：注册自身到全局 async 列表
3. notifier 检测到全部 endpoint 到齐 -> 依次调 `bound()` -> `complete()`
4. `complete()` 里构建 media pipeline、注册 /dev/videoN

**排查口诀：`/dev/videoN` 不出现，先看 sensors/bridges 是否全部 bound**（dmesg 搜 `v4l2-async`），再查格式协商。

## 4. 用户态标准采集流程（ioctl 主线）

```c
open("/dev/video0")
VIDIOC_QUERYCAP          // 能力：capture/output/m2m、多平面？
VIDIOC_S_FMT             // 协商格式（宽高/pixelformat，如 RAW12 是 'RG12'，YUV422 是 'YUYV'）
VIDIOC_REQBUFS(count=4)  // 分配缓冲（MMAP 模式）
for each buf: VIDIOC_QUERYBUF + mmap()
for each buf: VIDIOC_QBUF()        // 全部入队
VIDIOC_STREAMON()                  // -> vb2 start_streaming -> 传感器出流
loop {
    poll(fd)                       // 等 buffer done
    VIDIOC_DQBUF()                 // 取一帧处理
    VIDIOC_QBUF()                  // 用完还回去
}
VIDIOC_STREAMOFF()
```

### 内存模式

| 模式 | 分配方 | 典型用途 |
|---|---|---|
| V4L2_MEMORY_MMAP | 内核（vb2/heap）分配，用户 mmap | 默认，最常用 |
| V4L2_MEMORY_USERPTR | 用户分配，内核钉页 | 特殊对齐要求 |
| V4L2_MEMORY_DMABUF | 外部 dma-buf fd 导入 | **零拷贝链路**：heap 分配的 buffer 直接交给采集节点，同一条链再给 NPU（对应简历相机->NPU 零拷贝） |

### vb2 buffer 状态机

```
QUEUED -> (硬件填充) -> DONE -> (DQBUF) -> 用户持有 -> (QBUF) -> QUEUED
```

丢帧排查：sequence 跳号 = 中间有帧没按时到位（行缓冲溢出/SerDes 错误/传感器丢帧都会走到这里，对应简历 Double Pixel 丢帧问题的观测点）。

## 5. 控制与格式协商

- **ctrl 体系**（`v4l2-ctrls`）：曝光/增益/帧率都是 ctrl（`v4l2_ctrl_handler` + `V4L2_CID_*`），`v4l2-ctl -L` 可枚举
- **pad 格式协商**：`set_fmt/get_fmt` 在 subdev 间逐级传播；`mbus_code` 是 subdev 间总线格式（如 `MEDIA_BUS_FMT_SRGGB12_1X12` = RAW12）
- resume 相关：SERDES 的链路模式、Tunnel/Pixel 也以私有 ctrl 暴露给中间件

## 7. 面试问答

**Q: /dev/videoN 一直不出现，怎么查？**
分层：传感器/桥是否 probe（I2C 能否通信）-> v4l2-async 是否 complete（dmesg）-> 格式协商是否成功 -> vb2 分配是否失败。`media-ctl -p` 看拓扑断在哪。

**Q: s_stream 和 enable_streams 的区别？**
s_stream 是全局开关；enable_streams 按 pad/流粒度（多流传感器一路 RT 一路 YUV 时必须按流控制），新内核主推后者。

**Q: 怎么实现零拷贝？**
DMABUF 模式：heap 分配的 dma-buf 经 VIDIOC_QBUF(dmabuf fd) 导入采集节点，帧填好后同一 fd 传给 NPU 进程（SCM_RIGHTS），全程无 memcpy。

**Q: sequence 号跳了说明什么？**
该帧在硬件/中断/vb2 环节没能及时交付。结合驱动丢帧计数、SerDes 错误计数、CSI RX 错误区分是传感器丢、链路错、还是软件回收慢。

**Q: media controller 为什么需要？**
多 subdev 拓扑（sensor->ser->deser->CSI->ISP->resizer）需要统一描述与配置路由/格式的框架；没有它，每级驱动的初始化顺序和格式传播都要手工约定。
