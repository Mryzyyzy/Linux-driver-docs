核心先记一句：

> GIC “接收外设中断”不是软件主动 `read` 出来的，而是硬件中断线被外设拉起后，GIC 硬件自动把对应 INTID 标记为 pending。Linux 代码主要负责：提前配置 GIC，等 CPU 进中断后再读取 GIC 的 IAR 寄存器确认是哪一路中断。

---

# 1. 先看整体链路

以 UART 为例：

```text
UART 收到数据
    ↓
UART 控制器置位 RX 中断状态
    ↓
UART 中断输出线有效
    ↓
GIC 硬件接收到这根线
    ↓
GIC 把对应 SPI 标记为 pending
    ↓
GIC 根据优先级/路由通知某个 CPU
    ↓
CPU 进入 IRQ exception
    ↓
Linux 调用 gic_handle_irq()
    ↓
读取 IAR，拿到中断号
    ↓
分发给 UART 驱动 handler
```

---

# 2. 设备树告诉内核：UART 中断接到哪里

例如 STM32 UART8：

```dts
uart8: serial@40019000 {
	compatible = "st,stm32h7-uart";
	reg = <0x40019000 0x400>;
	interrupts-extended = <&exti 33 IRQ_TYPE_LEVEL_HIGH>;
	clocks = <&rcc UART8_K>;
	status = "disabled";
};
```

关键是：

```dts
interrupts-extended = <&exti 33 IRQ_TYPE_LEVEL_HIGH>;
```

意思：

```text
UART8 的中断接到 exti 控制器
中断号 33
高电平触发
```

如果是直接接 GIC，常见形式可能是：

```dts
interrupts = <GIC_SPI 33 IRQ_TYPE_LEVEL_HIGH>;
```

意思：

```text
这是 GIC 的 SPI 中断
硬件中断号是 33
高电平触发
```

# 3. GIC 初始化：打开接收能力

代码位置：

irq-gic-v3.c

初始化里有：
[[set_handle_irq注册与解耦逻辑]]
```c
set_handle_irq(gic_handle_irq);

gic_cpu_sys_reg_enable();
gic_prio_init();
gic_v3_dist_init();
gic_v3_cpu_init();
```

重点是：

```c
set_handle_irq(gic_handle_irq);
```

意思：

```text
以后 CPU 收到 IRQ，就调用 gic_handle_irq()
```

# 4. Distributor 初始化：允许 GIC 接收 SPI

在 `gic_v3_dist_init()` 里：

```c
/* Disable the distributor */
writel_relaxed(0, base + GICD_CTLR);
```

先关掉 Distributor。

然后配置 SPI：

```c
gic_dist_config(base, GIC_LINE_NR, dist_prio_irq);
```

这一步会配置很多 SPI 的默认属性，比如：

```text
优先级
触发类型
默认禁用/清 pending
```

最后打开 Distributor：

```c
val = GICD_CTLR_ARE_NS | GICD_CTLR_ENABLE_G1A | GICD_CTLR_ENABLE_G1;

writel_relaxed(val, base + GICD_CTLR);
gic_v3_dist_wait_for_rwp();
```

这表示：

```text
GIC Distributor 开始工作
允许 Group1 中断进入
```

可以理解为：

```text
GIC 总闸打开
```

# 5. 给 SPI 设置路由：这个中断送到哪个 CPU

还是在 `gic_v3_dist_init()`：

```c
affinity = gic_cpu_to_affinity(smp_processor_id());

for (i = 32; i < GIC_LINE_NR; i++)
	gic_write_irouter(affinity, base + GICD_IROUTER + i * 8);
```

`GICD_IROUTER` 用来设置 SPI 送到哪个 CPU。

意思：

```text
外设中断来了以后，GIC 要知道通知哪个 CPU
```

后面如果系统修改 IRQ affinity，会走：

```c
static int gic_set_affinity(...)
{
	...
	val = gic_cpu_to_affinity(cpu);
	gic_write_irouter(val, reg);
	...
}
```

# 7. IRQ core 会让 GIC 打开这一路中断

GIC 的 irq_chip：

```c
static struct irq_chip gic_chip = {
	.name		= "GICv3",
	.irq_mask	= gic_mask_irq,
	.irq_unmask	= gic_unmask_irq,
	.irq_eoi	= gic_eoi_irq,
	.irq_set_type	= gic_set_type,
	.irq_set_affinity = gic_set_affinity,
};
```

其中打开中断的是：

```c
static void gic_unmask_irq(struct irq_data *d)
{
	gic_poke_irq(d, GICD_ISENABLER);
}
```

`GICD_ISENABLER` 是 GIC 的中断使能寄存器。

也就是说：

```text
request_irq()
    ↓
IRQ core 配置这一路 IRQ
    ↓
调用 gic_unmask_irq()
    ↓
写 GICD_ISENABLER
    ↓
GIC 允许接收这一路外设中断
```

反过来关闭中断：

```c
static void gic_mask_irq(struct irq_data *d)
{
	gic_poke_irq(d, GICD_ICENABLER);
}
```

# 8. 设置触发类型：电平还是边沿

设备树里有：

```dts
IRQ_TYPE_LEVEL_HIGH
```

GIC 代码里对应：

```c
static int gic_set_type(struct irq_data *d, unsigned int type)
{
	...
	ret = gic_configure_irq(index, type, base + offset);
	...
}
```

它最终配置 GIC 的：

```text
GICD_ICFGR
```

作用：

```text
告诉 GIC 这根中断线是高电平触发，还是边沿触发
```

UART 这类外设常见是：

```text
level high
```

# 9. 真正“接收”的那一刻发生了什么？

这里没有一行 C 代码在“接收”。

真实过程是硬件自动完成：

```text
UART RX FIFO 有数据
    ↓
UART 控制器输出 IRQ 信号
    ↓
GIC 硬件采样到该信号
    ↓
GIC 内部把对应 INTID 置为 pending
```

如果这一路 IRQ 满足：

```text
已 enable
优先级允许
目标 CPU 在线
CPU 没屏蔽 IRQ
```

GIC 就向 CPU 发 IRQ。

---

# 10. CPU 进中断后，软件第一次碰 GIC

CPU 进入 IRQ exception 后，会进：

```c
static void __exception_irq_entry gic_handle_irq(struct pt_regs *regs)
```

普通情况进入：

```c
__gic_handle_irq_from_irqson(regs);
```

里面关键代码：

```c
irqnr = gic_read_iar();
```

这一步非常关键。

`gic_read_iar()` 读取的是 GIC CPU interface 的 IAR：

```text
ICC_IAR1_EL1
```

含义：

```text
CPU 问 GIC：当前你送给我的中断号是多少？
```

同时这一步也会把 GIC 中断状态从：

```text
Pending -> Active
```

---

# 11. 拿到中断号后分发

读到 `irqnr` 后：

```c
__gic_handle_irq(irqnr, regs);
```

里面：

```c
static void __gic_handle_irq(u32 irqnr, struct pt_regs *regs)
{
	if (gic_irqnr_is_special(irqnr))
		return;

	gic_complete_ack(irqnr);

	if (generic_handle_domain_irq(gic_data.domain, irqnr)) {
		WARN_ONCE(true, "Unexpected interrupt (irqnr %u)\n", irqnr);
		gic_deactivate_unhandled(irqnr);
	}
}
```

核心是：

```c
generic_handle_domain_irq(gic_data.domain, irqnr);
```

意思：

```text
把 GIC 硬件中断号 irqnr 交给 Linux IRQ core
```

IRQ core 再找到之前 `request_irq()` 注册的 handler。

例如 STM32 UART：

```text
stm32_usart_interrupt()
```

# 12. UART handler 处理设备侧中断

STM32 UART handler：

```c
static irqreturn_t stm32_usart_interrupt(int irq, void *ptr)
{
	struct uart_port *port = ptr;
	...
	sr = readl_relaxed(port->membase + ofs->isr);
	...
}
```

它读取 UART 自己的状态寄存器：

```text
USART ISR
```

判断是：

```text
RX 中断？
TX 中断？
超时？
错误？
唤醒？
```

然后清 UART 自己的中断状态。

注意：

```text
GIC 只负责把中断送到 CPU
UART handler 必须清 UART 设备侧的中断源
```

否则 UART 中断线一直有效，GIC 会再次收到中断。

---

# 13. 最终 EOI：告诉 GIC 处理完了

GIC 的 irq_chip 里：

```c
.irq_eoi = gic_eoi_irq,
```

处理完设备 handler 后，IRQ core 会调用 GIC EOI。

作用：

```text
告诉 GIC：这个中断我处理完了
```

GIC 状态从：

```text
Active -> Inactive
```

如果 UART 侧还没清干净，中断线还是高电平：

```text
GIC 又会把它置 Pending
```

于是再次进中断。

---

# 14. 把流程压缩成一句代码链

```text
设备树 interrupts
    ↓
irq domain 映射 hwirq -> virq
    ↓
request_irq() 注册 handler
    ↓
gic_unmask_irq() 写 GICD_ISENABLER
    ↓
UART 硬件拉中断线
    ↓
GIC 硬件置 pending
    ↓
CPU 进入 IRQ
    ↓
gic_handle_irq()
    ↓
gic_read_iar()
    ↓
generic_handle_domain_irq()
    ↓
stm32_usart_interrupt()
    ↓
gic_eoi_irq()
```

---

最核心理解：

```text
“接收外设中断信号”发生在 GIC 硬件里；
Linux 代码负责提前配置 enable/type/route；
等 CPU 被打断后，软件通过 gic_read_iar() 知道 GIC 收到了哪一路中断。
```
